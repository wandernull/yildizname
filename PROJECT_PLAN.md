# Project Plan — Yıldızname

## Vision
A premium, mystical, Turkish-language astrology reading experience that feels nothing like a SaaS product. The reader should feel they have walked into an Ottoman observatory, not opened a web form. The free preview must be strong enough that the 349,99 ₺ unlock feels overdue, not pushy.

## Phases

### Phase 1 — Scaffold + free preview (status: done)
- Goal: end-to-end demo from landing → form → loading → free section + locked previews → mock unlock, all on Workers + Hono + D1.
- Scope: design system, Cormorant + Noto Serif from Google Fonts, canvas star field, Moon + shooting stars, multi-step form, Claude prompt + JSON parsing, D1 `readings` schema, mock `PaymentProvider`, TTS audio, print-to-PDF, GitHub Actions deploy on push to `main`.

### Phase 2 — Real payments + persistence hardening (status: DONE — live)
- Goal: durable readings + real payment flow.
- Shipped: live Stripe Checkout (inline `price_data`, automatic_tax inclusive, tr-TR locale, invoice creation, promo codes) + signed webhook `/api/stripe/webhook` (Web Crypto HMAC, idempotent) flips `unlocked` in D1. Turkish-localized invoice (pre-created Customer with `preferred_locales=['tr']`). Brand+entity attribution + KVK/VAT on the invoice + below the Pay button. `MockPaymentProvider` deleted. Admin: `/admin` (funnel), `/admin/ratings`, `/admin/ops` (reset-payment). Migrations 0003–0006 applied to prod.
- Not done (deferred): receipt email from our own domain (Stripe sends from its domain; custom-domain Stripe emails are a paid tier), Stripe custom Checkout domain (paid tier), refund-on-`charge.refunded` automation (manual via Ops page / CLI).

### Phase 3 — Share + polish (status: partially done)
- Shipped: OG share image (1200×630) + favicon/apple-touch-icon brand pack, wired into all pages; shareable read-only link already worked (locked preview is the hook); in-app-browser-safe share (clipboard fallback); legal pages (/gizlilik, /kosullar) + site-wide footer (now the action bar).
- Not done: server-rendered PDF stored in R2 + emailed (still `window.print()`).

### Phase 4 — TTS upgrade (status: done — ElevenLabs)
- Shipped in Phase 1 actually: ElevenLabs `eleven_multilingual_v2`, voice `J17lijyP1BHYcM7ld0Rg`, R2-cached. Cost-optimized further (see 2026-05-27 split). Remaining: clone a bespoke müneccim voice once paying signal justifies it (swap `ELEVENLABS_VOICE_ID`).

### Phase 5 — Conversion + analytics + admin (status: DONE)
- Funnel analytics (viewer_ip, client_kind, scroll/listen/click flags) surfaced in `/admin`. Paid feedback (rating + comment) in `/admin/ratings`. Lean CTA system → single persistent action bar (primary pill + secondary icons, state-aware). karakterinOzu free preview cut to 1/3 with inline literary paywall + cost-optimized two-file audio. Admin Ops page for reset-payment.

## Decisions log
A reverse-chronological log of meaningful decisions. Each entry: date, decision, reasoning, alternatives considered.

- **2026-05-28 — Promo generation from the Ops page (Phase 2a), backed by a new `promos` table (migration 0008).** A reading can accrue several apology/win-back codes over time, so promos live in their own table (1 reading → many promos), not a column on `readings`. `POST /api/admin/generate-promo/:id` reads `percent` from the form (default 25, clamp 1–100), creates a Stripe coupon (`duration=once`, `metadata[reading_id]`) + a single-use promotion_code `YILDIZ-XXXX` (30-day expiry via `PROMO_EXPIRY_DAYS`, `max_redemptions=1`, 1 retry on code collision), stores the mirror locally, PRG-redirects. **Each click = 1 coupon + 1 promotion_code (1:1:1 with the `promos` row)** — kept per-reading-isolated (coupon carries that reading's `reading_id` + exact `percent_off`) rather than one shared "25% off" coupon; coupons are free/unlimited and redemption status lives on the promotion_code anyway, so sharing buys nothing. **We do NOT store a local `redeemed` flag** — Stripe is source-of-truth; the Ops page reads live `times_redeemed` via `fetchPromoRedemptions` (Promise.all) to show kullanıldı/kullanılmadı. Code alphabet excludes O/0/I/1. **Stripe API-version gotcha:** the account's *default* API version rejects the classic top-level `coupon` param on `/v1/promotion_codes` ("Received unknown parameter: coupon", under Stripe's coupon/discounts refactor). Fix: pin `Stripe-Version: 2024-06-20` (`STRIPE_PROMO_API_VERSION`) on the **promo requests only** — checkout-session/customer/webhook stay on the account default (they work, and pinning could change their response parsing). Phase 2b (send-via-Resend) deferred: needs Resend + a verified sending domain (SPF/DKIM/DMARC) + `RESEND_API_KEY`.
- **2026-05-28 — Admin Ops page (`/admin/ops`, "İşlemler" tab) for destructive actions, starting with reset-payment.** Reasoning: destructive mutations don't belong on the read-only Funnel/Puanlar dashboards (misclick safety + read-vs-write separation); a dedicated page is also the natural home for future ops (manual comp/unlock, resend invoice, lookup by Stripe session). Flow: ID lookup form → state card → red "Ödemeyi geri al →" gated by a `confirm()` (echoes the id, never the user name, to keep the inline JS string safe) → `POST /api/admin/reset-payment/:id` → PRG 303 back. `db.resetPaymentForAdmin` mirrors `scripts/reset-paid-one.sh` (clears unlocked + Stripe metadata + feedback). Does NOT refund on Stripe (separate Dashboard action). Paid funnel rows get a dim "işlem →" deep-link to the pre-filled ops page. **Open question:** whether reset should also clear feedback (currently does, matching the CLI) — revisit if it feels wrong.
- **2026-05-28 — Consolidated all bottom CTAs into ONE persistent, state-aware action bar.** Reasoning: the result page had sprawled to 3–4 ways to open the unlock modal + 4 disabled buttons + a payment/actions cluster duplicated top and bottom + a "Yeni okuma" footer that was dead-last and never seen. Replaced the unlock sticky + feedback sticky + post-actions row + footer with a single fixed-bottom bar: a primary pill + a row of small icon+label secondaries, adapting per state. Free = "Kaderinin tamamını aç →" pill + ↗Paylaş + ↻Yeni. Paid = "▶ Baştan Sona Dinle" pill + ⬇PDF + ↗Paylaş + ✦Yorum + ↻Yeni (Yorum drops off after feedback given). Established a **3-tier CTA rule** (primary gold-fill / secondary outline-icon / inline gold-italic link). Net −150 lines. `wireStickyAndModal`→`wireUnlockModal`, `wireFeedback`→`wireFeedbackModal` (modal-only, return `openModal`). Alternatives considered: flat icon toolbar (rejected — free-state unlock loses dominance); expanding FAB (rejected — new paradigm, less discoverable). Interim before this: a "Lean" redesign with a single unlock card + still-disabled audio/PDF buttons — superseded same day by the action bar.
- **2026-05-28 — Paid-only rate + feedback (★ 1-5 required + optional comment), one-shot.** Migration 0006 adds `feedback_rating/text/at` + `viewed/clicked_feedback_cta`. `POST /api/feedback/:id` is paid-gated (403 if unlocked=0), first-submission-wins. - **2026-05-27 — karakterinOzu free preview cut to ~1/3 (sentence-bounded) with an inline literary paywall, and audio split into two cached files to avoid double-paying ElevenLabs.** The free response returns only the 1/3 `preview` + a one-sentence blurred `karakterinOzuTeaser` (the only leaked sentence of the rest); after it, an inline gold-italic "Devamını oku →" opens the unlock modal. - **2026-05-23 — Single tier at 349,99 ₺ (text + audio bundled), price hidden on the sticky CTA, revealed in a reveal modal.** Reasoning: previous two-tier idea (249,99 text-only / 349,99 text+audio) is shelved — the audio is core to the experience, splitting it created two cheap-feeling SKUs instead of one clear premium offer. New mobile-only sticky bar at the bottom uses "Devamını oku →" copy (no price visible while scrolling so it doesn't break motivation); tapping opens an "Mührü kır" modal that shows the value-prop body and the 349,99 ₺ price prominently, with the same "Kaderinin tamamını aç →" CTA as the inline buttons. The reveal is a single click delay, not a hidden-price pattern — Turkish e-commerce law (Mesafeli Sözleşmeler Yönetmeliği) requires price visible before commit-to-pay, and it is. Two places hardcode the display string (inline-button label in `views.js` + the modal price element in the template) — leaving a TODO comment in views.js calling that out so a future config-driven price would update both.
- **2026-05-22 — TTS via ElevenLabs `eleven_multilingual_v2` + stock male voice `J17lijyP1BHYcM7ld0Rg`, R2-cached for 15 days.** Reasoning: browser `speechSynthesis` Turkish voices sound like 1990s phonebook readers and were breaking immersion. ElevenLabs is the highest-quality commercial TTS with reliable Turkish support; cost (~$2.80 per full uncached reading) is comfortable inside the 250 TRY margin once cache amortizes replays. Phase 2 will replace the stock voice with a cloned müneccim voice once paying-customer signal validates the investment. Alternatives considered: Fish Audio (cheaper but Turkish not officially supported), Cartesia (similar to ElevenLabs but unproven on Turkish for us), Google Chirp HD (cheaper but less mystical timbre), self-hosted XTTS on Replicate (operational overhead not worth the saving at this scale).
- **2026-05-22 — On-demand TTS, lazy per section, no pre-warming at unlock.** Reasoning: keeps spend proportional to actual listening — users who pay but only listen to 2 sections cost $0.50 in TTS instead of $2.50. R2 15-day cache means replays are free regardless. Alternatives considered: pre-warm all 9 sections at unlock (rejected — wastes spend on partial listeners; the perceived "delay on first Dinle click" is acceptable since the audio player surfaces a loading state).
- **2026-05-22 — Audio bundled into the 250 TRY unlock, not sold as a separate add-on.** Reasoning: the voice IS the experience. Splitting it as an upsell would add a second decision point right after the first one (kills conversion) and break the mystical immersion. Alternatives considered: 250 TRY text + 50 TRY voice add-on (rejected — friction + cheapens both products).
- **2026-05-22 — Autoplay `karakterinOzu` on first arrival from the journey path, with volume fade-in 0→100% over 2s, pulse on the play button if blocked.** Reasoning: after a 2-minute mystical loading screen, silence on the result page is a UX cliff. The user just clicked through; the gesture history allows autoplay on most browsers (Chrome/Firefox). iOS Safari silent-switch will block — that's a hard limit, the pulse animation handles it. Guarded by a one-shot `sessionStorage` flag (`yildizname:from-journey`) set right before `/loading → /result` navigation and consumed once on mount; shared links, refreshes, and back-navigation deliberately do NOT autoplay. Alternatives considered: opt-in play only (rejected — kills the hook); fixed-time pre-roll silence (rejected — felt off).
- **2026-05-22 — `karakterinOzu` audio prepends the `kapakSözü` at synth time.** Reasoning: the kapakSözü is the most evocative phrase of the reading; making it the first thing the user hears (rather than the longer prose) maximises the hook. Em-dashes also injected after sentence terminators at synth time for slower prosody. None of this pollutes the stored D1 sections — text shaping happens only in `src/lib/tts.ts → buildSpeechText()`.
- **2026-05-22 — R2 cache writes buffer the tee'd branch into a Uint8Array before `R2.put`.** Reasoning: R2.put requires a body with known content length; ElevenLabs streams as chunked encoding (no `Content-Length`). Passing the stream directly threw `TypeError: Provided readable stream must have a known length` — confirmed via `wrangler tail`. Buffering is ~2 MB per concurrent reading, well within memory limits. Client branch still streams in parallel, so listener UX is unchanged. Alternatives considered: `FixedLengthStream` (need length up-front, we don't know it); not caching at all (would cost 5× more on replays).
- **2026-05-21 — Anthropic call uses tool-use, not text-JSON.** Reasoning: asking the model to produce a JSON object as text was unreliable — long Turkish prose (~4000 chars) tripped escaping bugs (observed an unescaped character at position 1419 of the response, breaking `JSON.parse`). With a `submit_reading` tool + `tool_choice`, Anthropic constructs the JSON server-side and the streamed `input_json_delta` chunks always concatenate to a valid document. Alternatives considered: post-hoc JSON repair (rejected — fragile), constrained text grammar (Anthropic doesn't expose one).
- **2026-05-21 — `/api/generate` is synchronous and uses Anthropic's SSE streaming inside the Worker, not `executionCtx.waitUntil`.** Reasoning: on Workers Free, `waitUntil()` tasks get cancelled shortly after the response is sent — confirmed via `wrangler tail`: *"waitUntil() tasks did not complete within the allowed time after invocation end"*. Compounding it, Workers' 100-second subrequest timeout would have killed a non-streaming Anthropic call anyway (full generation runs ~2–3 minutes). Streaming with `stream: true` returns headers in <1s so the subrequest timeout never fires, and keeping the inbound client connection open lets the Worker hold the LLM stream alive for its full duration — no `waitUntil`, no plan upgrade. Alternatives considered: Workers Standard ($5/mo) to get a longer `waitUntil` budget (rejected — works without paying); Cloudflare Queues (rejected — paid plan); polling architecture (rejected — only useful if the work runs in the background, which Free can't reliably do).
- **2026-05-21 — Canonical hostname is the bare apex `yildizna.me`; www 301s to apex.** Reasoning: simpler shareable links, one canonical for SEO. Implemented as a Hono middleware that checks the `Host:` header and 301s any `www.*` request to the apex with path + query preserved — no zone-level Redirect Rule needed, so the narrow CI token still works. Alternatives: CF Single Redirect Rule (rejected — needs Zone:Edit perms that the CI token lacks; would have forced a token expansion the user didn't want).
- **2026-05-21 — Worker Custom Domains attached out-of-band via the CF API, not via wrangler.toml `routes`.** Reasoning: the CI's `CLOUDFLARE_API_TOKEN` is scoped to Workers:Edit only. A `routes = [..., custom_domain = true]` block in wrangler.toml would force CI to attempt zone-level reconciliation on every deploy and fail. By creating the bindings via direct `PUT /accounts/{id}/workers/domains` once, the custom domains persist in the CF account and CI deploys just push code without touching them. The decision is documented in `wrangler.toml` itself so future agents don't add a routes block by reflex. Alternatives: expand the CI token (rejected — user opted to keep it narrow).
- **2026-05-21 — Wrangler pinned to v4 (not v3) from day one.** Reasoning: wrangler 3's bundled miniflare pins `zod@3.22.3`, which violates `@anthropic-ai/sdk`'s peer dep `^3.25.0 || ^4.0.0` and breaks `npm ci` on CI. v4 ships with a newer miniflare and resolves cleanly. Alternatives: add a `zod` override in package.json (rejected — masks the root cause), pin `@anthropic-ai/sdk` to an older version (rejected — loses SDK features).
- **2026-05-21 — Workers Assets configured with `html_handling = "none"` + `not_found_handling = "none"`.** Reasoning: the default `auto-trailing-slash` HTML handling 307-redirects non-extension paths like `/form` to `/`, so the Worker's SPA fallback never runs. Explicitly disabling that lets the Worker handle non-asset, non-API paths and serve `/index.html` from the ASSETS binding. Alternatives: `not_found_handling = "single-page-application"` (rejected — also serves index.html for /api/* misses).
- **2026-05-21 — Switched the entire stack from Next.js to Cloudflare Workers + Hono + D1.** Reasoning: the global standards in `~/.claude/CLAUDE.md` specify Workers + Hono as the web default; the first scaffold violated that and the user asked to rebuild strictly to standard. Alternatives considered: keep Next.js (rejected — violates standards), Workers + Hono + Pages for the frontend (rejected — extra deploy surface; Workers Assets serves static fine).
- **2026-05-21 — Vanilla HTML/CSS/JS frontend, no bundler.** Reasoning: global standards say "Vanilla HTML/JS served from the Worker, unless a frontend framework is explicitly requested." User affirmed strict standards. Animations move to canvas + CSS keyframes + Web Animations API. Alternatives: React+Vite SPA (rejected — adds build step and JS payload; standards explicitly say vanilla by default).
- **2026-05-21 — SPA shell via History API, served by SPA fallback in the Worker's `notFound` handler.** Reasoning: keeps the persistent star-field canvas across "screen" changes, which is essential for the mystical atmosphere; otherwise every navigation flashes the background. Alternatives: separate HTML files per route (rejected — kills the persistent atmosphere); `not_found_handling = "single-page-application"` on the assets binding (rejected — would also catch `/api/*` paths, harder to keep clean).
- **2026-05-21 — Stripe (not iyzico) as the eventual payment provider.** Reasoning: user explicitly chose Stripe. Alternatives: iyzico (rejected — user-vetoed).
- **2026-05-21 — Mock payment behind a `PaymentProvider` interface for v1.** Reasoning: lets the full UI flow ship and be tested end-to-end before the user wires real Stripe themselves. Drop-in replacement when Stripe is added.
- **2026-05-21 — `claude-sonnet-4-5` with `max_tokens: 4000` and strict JSON validation + one retry.** Reasoning: Sonnet has the tone for Ottoman-müneccim Turkish; the SDK's `messages.create` works directly inside Workers (it's fetch-based). Alternatives: Opus (overkill cost-wise for one-shot generation), Haiku (lacks the literary depth this needs).
- **2026-05-21 — Browser Web Speech API for TTS in v1.** Reasoning: zero per-request cost, ships everywhere, Turkish voice quality on macOS/iOS is acceptable. Phase 4 will revisit.
- **2026-05-21 — In-app SPA routing (History API), Worker's `notFound` falls back to `/index.html`.** Reasoning: cleanest division of concerns — assets serve real files, Worker serves dynamic API + SPA shell. Alternatives: hash-based routing (rejected — uglier shareable URLs).

- **Migration 0002 (`status` / `error` columns) is currently a no-op on the sync path.** Kept for two reasons: (1) it's already applied to local + remote D1 and reverting it is risky; (2) if we ever do graduate to a paid plan with Queues / longer `waitUntil`, the columns are exactly what an async consumer would need to write. Don't drop them.

## Operational notes (gotchas for future agents)
- **Sourcing `~/.gizem-creds` directly fails in non-interactive shells** — its gvm init line errors with "GVM_ROOT not set". Workaround used all session: run commands via `/bin/bash --noprofile --norc -c '…'` and extract the one var you need, e.g.
  `TOKEN=$(grep -E '^(export )?CLOUDFLARE_API_TOKEN=' ~/.gizem-creds | head -1 | sed -E 's/^(export )?CLOUDFLARE_API_TOKEN=//' | tr -d "\"'")`.
- **git push** still needs the one-off token URL (Keychain offers the wrong `baranbartu` account): `git -c credential.helper= push "https://wandernull:${GH_TOKEN}@github.com/wandernull/yildizname.git" main`.
- **wrangler is a devDep** — invoke via `npx wrangler …`, not bare `wrangler`.
- **GitHub had a major Actions outage on 2026-05-26** that briefly surfaced a misleading "Your account is suspended" error in CI logs — the account was fine (verified via `gh api user`). If CI deploys mysteriously fail, check status.github.com before assuming an account problem.
- **Migration discipline:** always `npm run db:migrate:remote` BEFORE pushing code that reads new columns, or every read 500s until the schema catches up.
