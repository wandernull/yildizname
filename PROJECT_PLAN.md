## Decisions log
A reverse-chronological log of meaningful decisions. Each entry: date, decision, reasoning, alternatives considered.

- **2026-07-07 — Chunked TTS architecture (v4) to fix mobile audio cut-off + reduce bounce waste.** Long-standing bug: on mobile browsers (iOS Safari + in-app browsers) locked-section audio was cutting off near the end. Root cause: our streaming TTS response used chunked-transfer-encoding (no `Content-Length`) — mobile `<audio>` needs a known length to play a long stream to the end. **Diagnosis first**: user pushed back on shipping without knowing root cause; empirical byte-counting logs confirmed `clientBytes == r2Bytes` (server-side tee was fine, browser was ending playback early on the chunked stream); confirmed the issue was mobile-only; confirmed cached (R2) plays fine because R2 responses always carry `Content-Length`. **New architecture**: each section is split into ~180-char sentence-packed chunks at synth time (`splitIntoChunks` in `src/lib/text.ts`, greedy sentence-boundary regex mirroring `splitKarakterinOzu`); each chunk synthesized via ElevenLabs' **non-streaming** endpoint (returns the full MP3 buffer with known length); cached per-chunk in R2 at `tts/v4/{readingId}/{section}/{chunkIdx}.mp3`; new route `GET /api/tts/:readingId/:section/:chunkIdx` returns one chunk with explicit `Content-Length`. `getChunkCount()` per section rides on the `/api/reading/:id` done response so the frontend knows how many chunks to walk. **Client-side prefetch pipeline**: after the first ship (sequential-only walk had audible mid-section pauses waiting for next-chunk synth), added a 2-chunks-ahead background `fetch()` prefetch triggered on the `playing` event — responses carry `Cache-Control: public, max-age=1296000, immutable` so subsequent `audio.src` switches load from the browser HTTP cache instantly (~10ms seam vs ~3s wait). Applied to both the per-section player (`makeAudioPlayer`, one hook on the `playing` event covers initial + advance + resume) and the chain "Baştan Sona Dinle" queue (own hand-rolled walk, own `chainPrefetch` state, own `AbortController`). PREFETCH_AHEAD=2 caps total concurrent upstream at 3 (1 playing + 2 prefetching), matching the ElevenLabs Starter concurrency cap. **karakterinOzu funnel preserved**: the 1/3 preview vs 2/3 rest split lives at the text layer (`splitKarakterinOzu`); chunking happens WITHIN each side, so the free-preview cost optimization survives. Short sections (< ~60s of estimated audio at 0.075 s/char) stay monolithic via a `shouldChunk()` gate — no chunk seams introduced where they aren't needed. **Cost profile**: worst-case bounce cost dropped ~4× vs v3 monolithic (~30-45s of TTS synthesized on bounce vs ~120-180s per section). Prefetched-but-unheard chunks still land in R2 via `ctx.waitUntil()`, so no synth is truly "wasted" — next visitor gets them free. **Cleanup**: deleted the v3 monolithic path entirely (`ttsKey`, `isRestEmptyFor`, `fetchCachedAudio`, `synthesizeStream`, `bufferAndStore`, plus the byte-counting diagnostic logs from the `chore(tts): log client vs R2 byte counts` commit that motivated this work). `tts.ts` went from ~390 to ~225 lines despite gaining functionality. **R2 prefix bumped v3→v4**; old v3 keys age out via the 15-day lifecycle rule (dead weight, but negligible — a few GB × 15 days is pennies). **Tested on iOS Safari, Android, and web**; user reported "all worked neatly" including chain play. Rollback path clean: `wrangler rollback` restores v3 code; v3 R2 keys still readable until lifecycle sweep. Known post-deploy watch: `wrangler tail | grep '\[tts\]'` for `elevenlabs chunk non-2xx` (would signal 429s from the ElevenLabs 3-concurrent global cap) and `R2 chunk put failed`; ElevenLabs dashboard for the re-synth burst as v3-cached readings replay under v4 keys.
- **2026-06-29 — Async generation via Workers Paid + Cloudflare Queues (the big refactor).** /api/generate used to be synchronous: the Worker held the inbound HTTP connection open for ~2–3 minutes while reading Anthropic's SSE stream and writing the finished row to D1. On mobile this was a cliff — in-app browsers (Instagram, TikTok, Facebook, X) aggressively reclaim memory from backgrounded tabs, and iOS Safari kills tabs after a few minutes of screen lock; either case aborted the LLM call mid-flight and left the row stuck `status='pending'` forever. Now: /api/generate is the **producer** (insert row + `GENERATION_QUEUE.send({readingId, baseUrl})` + return `{id, status:'pending'}` in ~100ms); the Worker's **`queue()` consumer** runs the LLM call independently of any inbound connection. **Workers Paid prerequisite ($5/mo flat)** — Free plan's `executionCtx.waitUntil()` is killed before a 2-min LLM finishes (hit this in May, see the original sync-flow decision) and the 10ms-CPU cap would shred mid-stream anyway; Queues is paid-tier. Audited every Free-plan workaround before upgrading (cron polling, external services, shorter generation, etc.) — all dead-ends. Queue config: `max_batch_size=1`, `max_retries=3`. Consumer is idempotent on redelivery (rechecks status before doing work). Migration 0002's `status`/`error` columns (no-op since launch — the original sync-flow decision called it out as "kept in case we ever go async") finally pay off — consumer calls `markReadingPending`→`markReadingDone`→`markReadingFailed`, frontend polling branches on status.

  **Loading-screen escape hatch.** Form + ritual unchanged at the front of the funnel. After /api/generate returns the id, the URL is `history.replaceState`-swapped to `/okuma/:id` (no remount) so it becomes meaningful immediately — shareable, refreshable, bookmark-able. A floating panel under the mystical animation gives the user two recovery paths: type their email ("Hazır olunca yaz" → `POST /api/reading/:id/email`) or **"Bağlantını kopyala ve sonra kontrol et"** (clipboard write with `document.execCommand` fallback for non-secure contexts like 0.0.0.0). The reassurance text ("Eski usul saatler isterdi…") that used to sit as a separate footnote now lives inside this panel — single source of truth. Escape hatch renders in two states: "ask" form OR "confirmed" message ("✓ E-postanı aldım — yıldıznamen hazır olduğunda sana yazarım") — both same-tab post-submit AND across-tab/refresh (server returns `hasEmail: boolean` on every /api/reading/:id response). Direct visits to /okuma/:id during pending mount the **same** mystical loading view (moon + constellations + harfler + phased text + escape hatch) as the form ritual — shared `mountLoadingExperience()` helper. The "✗ ready spinner card while pending" mismatch is gone.

  **"Hazır" email.** Consumer fires a Turkish "Yıldıznamen hazır" email via Resend after `markReadingDone` IF `customer_email` is set on the row. Auto-linkified URL back to `/okuma/:id`. baseUrl comes from the queue message (producer captures `new URL(c.req.url).origin` at enqueue time — consumer has no inbound request). A race-handler on `POST /api/reading/:id/email` covers the case where the user submits email AFTER status flipped done (the consumer already finished and won't fire) — the endpoint fires the email immediately in that case.

  **Stripe Checkout email pre-fill.** If `customer_email` is set on the row (loading-screen capture), seed the Stripe Customer with it (`createStripeCustomer({readingId, email})`) so Checkout pre-fills the email field. Stripe locks the field as read-only by design (the email identifies the customer); accepted that intentionally — users who just typed an address ~2 minutes ago overwhelmingly want to use the same one. The cost of "they typed wrong but can't fix at Checkout" is mitigated by the admin email-sync tool. Two unsuccessful experiments to make it editable are documented inline in stripe.ts so future-us doesn't re-hit the same Stripe API walls: (a) `customer_update[email]=auto` is not a valid parameter, (b) `customer_email` on the Session conflicts with an attached `customer` (`"You may only specify one of these parameters: customer, customer_email"`).

  **No DB migration.** Reused `customer_email` from migration 0007 — the email captured at the escape hatch goes into the same column the Stripe webhook + admin sync already write to. Single source of truth; webhook overwrites with the verified Checkout email after payment (correct behavior).

  Net code change: ~+700 / −150. Phases shipped: 1 (queue infra) → 2 (DB helpers `insertReadingPending`/`markReadingDone`/`markReadingFailed`) → 3 (producer/consumer split + delete dead `insertReading`) → 4 (frontend polling + escape hatch + bounce-recovery on /okuma/:id) → 4.5 (unify the loading view across both contexts) → 5 (email endpoint + `sendReadingReadyEmail` + Stripe pre-fill). One commit, one prod deploy.

- **2026-06-10 — Birth date formatted as Turkish-natural "9 Mart 1989" in the LLM prompt instead of raw ISO `1989-03-09`.** A user reported their friend's reading (born `1989-03-09` = 9 March) was insistently talking about a September birth. Storage was correct (admin showed `1989-03-09`, ISO 8601 = March 9), but the prompt was passing the raw ISO string into an otherwise Turkish-language context. Turkish dates are conventionally **DD-first** (`DD.MM.YYYY`), so the model was flipping its read of `1989-03-09` to `YYYY-DD-MM` — treating `03` as the day and `09` as Eylül (September). **Scale:** affected any user born on day 1–12 of the month (~39% of all readings). Fix in `src/lib/llm.ts`: a `formatBirthDateTurkish()` helper parses the ISO string literally (no `new Date()` — avoids timezone day-shifts) and emits "9 Mart 1989" via a `TURKISH_MONTHS` array. Storage stays ISO (sortable, unambiguous in the DB and admin). The legacy readings already generated with the wrong-month interpretation aren't auto-fixed — the Ops page has no regenerate endpoint today; bad legacy readings would need a manual regenerate path if it becomes a real volume problem.

- **Sourcing `~/.gizem-creds` directly fails in non-interactive shells** — its gvm init line errors with "GVM_ROOT not set". Workaround used all session: run commands via `/bin/bash --noprofile --norc -c '…'` and extract the one var you need, e.g.
  `TOKEN=$(grep -E '^(export )?CLOUDFLARE_API_TOKEN=' ~/.gizem-creds | head -1 | sed -E 's/^(export )?CLOUDFLARE_API_TOKEN=//' | tr -d "\"'")`.
- **git push** still needs the one-off token URL (Keychain offers the wrong `baranbartu` account): `git -c credential.helper= push "https://wandernull:${GH_TOKEN}@github.com/wandernull/yildizname.git" main`.
- **wrangler is a devDep** — invoke via `npx wrangler …`, not bare `wrangler`.
- **GitHub had a major Actions outage on 2026-05-26** that briefly surfaced a misleading "Your account is suspended" error in CI logs — the account was fine (verified via `gh api user`). If CI deploys mysteriously fail, check status.github.com before assuming an account problem.
- **Migration discipline:** always `npm run db:migrate:remote` BEFORE pushing code that reads new columns, or every read 500s until the schema catches up.
